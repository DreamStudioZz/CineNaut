OPTION A

顶部全宽栏

保留顶栏结构，把搜索框从 34px 的挤压状态改成标题行下方的独立全宽栏，高度加到 44px。

优点
改动最小；搜索始终可见；输入框和联想列表都有完整宽度。
注意
仍在屏幕最上方，单手够不到；键盘弹出后可视区域会进一步压缩。
适用
不想大改结构，以浏览为主、搜索频率一般。

OPTION B

全屏搜索页

顶栏只留一个搜索图标，点开后进入独立的全屏搜索页，输入框、最近搜索和联想结果都获得完整空间。

优点
专注、键盘友好；联想和最近搜索不再被 34px 顶栏挤压；是 iOS / Android 的通用心智。
注意
多一次点击；返回路径必须清晰，否则容易迷失。
适用
搜索是高频核心操作，愿意为它单独做一层。
入口：顶栏搜索图标 · 点开后全屏

OPTION C

底部悬浮搜索条

把搜索入口放到屏幕底部、拇指自然落点，浏览时随时可以唤起；点击后进入 B 的全屏搜索页。

单手可达；不占顶栏；浏览和搜索的切换成本最低。
注意
会遮住底部内容，需要给内容预留 padding；要和 iPhone 安全区配合。
适用
手机端为主，希望搜索像原生 App 一样随手可用。

OPTION D

下拉搜索抽屉

从顶栏图标展开一层轻量抽屉，把搜索框和类型 / 地区筛选放在一起，不离开当前海报流。

优点
搜索与筛选一体；不离开当前页；比全屏搜索轻，返回成本低。
注意
仍从顶部出现；抽屉高度、键盘和滚动要处理好，否则容易顶到内容。
适用
搜索后经常要切分类 / 地区，或者希望保留当前浏览上下文。
入口：顶栏搜索图标 · 向下展开抽屉

怎么选

四套都只用现有 token 和 CSS，不改接口；选定后可以直接改顶栏与搜索弹层结构。

A

顶部全宽栏

改动最小

把搜索从 34px 挤压状态改成标题下方的独立全宽栏。

优点
结构不变，输入与联想空间立刻变好
注意
仍在最上方，单手够不到
B

全屏搜索

最专注

搜索图标进入独立全屏页，输入、最近搜索、联想都完整展开。

优点
键盘友好，系统原生心智，空间最充足
注意
多一次点击，返回路径要清晰
C

底部悬浮

最顺手

搜索条固定在拇指区，浏览时随时唤起，点击进入全屏搜索。

优点
单手可达，切换成本最低，最像原生 App
注意
遮挡底部内容，需要预留 padding 和安全区
D

下拉抽屉

搜索+筛选

从顶部展开轻量抽屉，搜索框与类型 / 地区筛选放在一起。

优点
不离开当前页，保留浏览上下文
注意
仍从顶部出现，抽屉与键盘高度要处理好
我的建议：移动端优先做 C + B——底部悬浮条负责“随手唤起”，点开后进入 B 的全屏搜索页； 如果暂时不想大改，先做 A；如果搜索后经常切类型 / 地区，选 D。
