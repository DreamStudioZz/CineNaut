怎么选

四套都只用现有 token 和 CSS，不改数据结构；选定后可以直接替换当前 pilot-skeleton-card。

A

蓝图推演

最稳

把等待过程画成一张正在绘制的 CAD 图纸，步骤、路径、探针都在同一张图上。

气质
工程、精确、可解释
优点
与 codegraph 身份最一致，信息密度高，用户知道 AI 在做什么
注意
网格和虚线较多，弹窗小时会略密
B

精工刻度

最安静

用一把精密直尺表达进度，只保留刻度、百分比和一条绿线。

气质
克制、高级、留白
优点
视觉噪音最低，和设置页的直尺轨道同源，加载快时也不突兀
注意
过程信息少，用户不知道具体卡在哪一步
C

打字机手账

最透明

把 SSE 的 Thought / Action / Observation 直接落成一行行执行日志。

气质
手账、终端、真实
优点
信息最透明，等待 20 秒时用户能看到每一步在推进
注意
等宽字较多，长片名需要换行处理
D

胶片倒计时

最有辨识度

借用电影胶片的倒计时片头，把「正在定位正片」变成一次放映前的等待。

气质
电影、仪式感、轻松
优点
和 CineNaut 的影视主题强绑定，记忆点最强
注意
最抢戏，频繁转存时可能显得慢；适合作为可选皮肤
我的建议：默认用 A 蓝图推演，信息量和品牌一致性最好； 如果担心 20 秒等待时用户焦虑，切到 C 打字机手账，把 SSE 节点直接摊开。 B 适合「加载很快、只想安静等一下」的场景，D 建议留作彩蛋或设置项。
