OPTION D

盘搜卡片化

针对转存弹窗里的「盘搜」：搜索框与筛选吸顶，AI 状态单独一行，结果从密集列表改成带推荐理由和明确主按钮的卡片。

优点
检索控件不再挤成一行；键盘弹起后仍能看到搜索框；「选用并转存」成为唯一主操作。
注意
卡片比列表占纵向空间，需要控制每屏数量；「查看全部」要继续用底部抽屉承接。
适用
主要在手机上下发转存，希望少滑动、少误触。
入口：转存弹窗 · 专家手动 · 盘搜结果卡片化

怎么选

四套都沿用现有 token 和组件，不改接口。A/B 解决入口，C 解决结果，D 解决盘搜，可以组合。

A

全屏搜索页

最专注

搜索图标进入独立全屏层，输入、最近搜索、联想都完整展开。

优点
键盘友好，空间充足，系统原生心智
注意
多一次点击，返回路径要清晰
B

底部搜索条

最顺手

搜索条固定在拇指区，浏览时随时唤起，点击进入全屏搜索。

优点
单手可达，切换成本最低
注意
遮挡底部内容，要预留 padding 和安全区
C

结果列表化

改动最小

保留现有入口，只把结果从三列网格改成带吸顶查询条的列表。

优点
信息完整，转存路径最短，风险低
注意
入口仍然偏窄，只解决结果段
D

盘搜卡片化

少误触

转存弹窗里的搜索与筛选吸顶，结果改成带推荐理由的卡片。

优点
控件不挤，主操作明确，键盘不挡结果
注意
纵向空间占用更大，需要抽屉承接全部结果
R

建议组合：B + C + D。底部搜索条负责「随手能搜」，全屏搜索层负责「搜得专注」，结果列表化负责「搜完能看懂」， 盘搜卡片化负责「最后一步不误触」。如果只想先落一版，C 的风险最低、收益最直接； 如果愿意多改一点，B + C 是最完整的手机查询体验。
